# Releasing openPedal

The desktop app and the iPad app are released separately, each with its own version,
tag and changelog. The shared core (DSP, graph, engine, server) goes into both.

## Products

| Product | Version source | Tag | Changelog | Installed with |
|---|---|---|---|---|
| Desktop (binary + web UI) | `version` in `Cargo.toml` | `desktop-vX.Y.Z` | `CHANGELOG.md` | `cargo build --release` |
| iPad app | `CFBundleShortVersionString` in `ios/Info.plist`, plus `CFBundleVersion` (build number, +1 on every release) | `ios-vX.Y.Z` | `ios/CHANGELOG.md` | xtool, see below |

The protocol version (`PROTOCOL_VERSION`, the `protocol` field in `state`) is not a product.
Bump it when a change breaks the protocol between the core and the UI, so an older client
cannot talk to a newer core (or the other way round). Mark that commit with a
`BREAKING CHANGE: protocol vN` footer (or a `!` after the type): git-cliff then lists it under
"Breaking changes" in both changelogs.

## Changelogs

`CHANGELOG.md` and `ios/CHANGELOG.md` are generated by [git-cliff](https://git-cliff.org) from
the Conventional Commits. Do not edit them by hand. `tools/release.sh` regenerates the changelog
of the product being released, with the new version on the commits since the last tag.
Configuration: `cliff.toml`.

Commit messages must be `type(scope): summary`, in English (see `CONTRIBUTING.md`). Only
`feat`, `fix`, `perf`, `refactor`, `docs` and breaking changes reach a changelog, grouped as
Features, Fixes, Performance, Refactor and Documentation. Older commits (Italian, not
conventional) are left out.

### Scope routing

| Scope | Desktop changelog | iPad changelog |
|---|:-:|:-:|
| `ui` | yes | no |
| `ios` | no | yes |
| `dsp`, `graph`, `engine`, `server`, `ffi` | yes | yes |
| `docs`, `nix`, `chore` | no | no |
| no scope, or other scopes | yes | yes |

Commits of types `test`, `build` and other unlisted types are never in a changelog. Release
commits (`chore(release): ...`) are skipped as well.

## Cutting a release

From a clean `master`:

```sh
tools/release.sh desktop 0.2.0 --dry-run   # show what would happen, change nothing
tools/release.sh desktop 0.2.0             # checks, version bump, changelog, commit, tag
git push origin master desktop-v0.2.0      # you push: the script never pushes
```

Replace `desktop` with `ios` and the version as needed, for the iPad app.

The script:

1. checks that the version is `X.Y.Z`, that you are on `master`, that the tree has no
   uncommitted changes (untracked files are ignored) and that the tag does not exist yet;
2. runs the checks: desktop: `cargo test`, `cargo clippy --all-targets -- -D warnings`,
   `npm run build` in `ui/`; iPad: `cargo test`, `ios/scripts/build-core.sh`,
   `ios/scripts/xtool.sh dev build`. `--skip-checks` skips them;
3. bumps the version (and refreshes `Cargo.lock` for the desktop);
4. regenerates the changelog of that product;
5. commits `chore(release): desktop vX.Y.Z` (or `ios vX.Y.Z`) and creates the annotated tag.

With `--dry-run` a dirty tree or a branch other than `master` only produces a warning.

## Installing the iPad release

Check out the tag (`git checkout ios-v0.1.0`), then follow `ios/README.md`, section
"Build with xtool": `nix develop -c ios/scripts/build-core.sh` and `ios/scripts/xtool.sh dev`
with the iPad connected and unlocked. Free Apple IDs sign the app for 7 days.

## Tags

Tags are annotated and never moved or reused. If a release is wrong, fix forward with a new
version.
